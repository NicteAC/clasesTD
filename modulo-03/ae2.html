😰 El Problema del CSS Desorganizado

❌ CSS Caótico
.header .nav a { color: blue; }
.sidebar .nav a { color: green; }
.btn { padding: 10px; }
.button { padding: 10px; }
.header .button { padding: 15px; }
div.content p.intro { ... }
✅ CSS Organizado
.nav__link { color: blue; }
.nav__link--sidebar { color: green; }
.button { padding: 10px; }
.button--large { padding: 15px; }
.content__intro { ... }

Consecuencias: Selectores duplicados, nombres sin significado, conflictos de especificidad, código imposible de mantener

🧱 Metodología BEM

Block Element Modifier - La convención más adoptada en la industria

Bloque

Entidad independiente con significado propio

.card .menu .form

Elemento

Parte interna del bloque que no existe sin él

.card__title .menu__item

Modificador

Varía apariencia, estado o comportamiento

.card--featured .button--disabled

Convención: bloque__elemento--modificador

Doble guion bajo (__) separa bloque y elemento • Doble guion (--) indica modificadores

📝 BEM en la Práctica - HTML

<article class="card">
    <img class="card__image" src="..." alt="...">
    <div class="card__content">
        <h3 class="card__title">Título de la tarjeta</h3>
        <p class="card__description">Descripción aquí...</p>
        <button class="card__button card__button--primary">Ver más</button>
    </div>
</article>

📖 Al leer el HTML puedes inferir inmediatamente la estructura y jerarquía sin necesidad de ver el CSS

🎨 BEM en la Práctica - CSS

Estructura (Bloque y Elementos)
.card {
    display: flex;
    flex-direction: column;
    border-radius: 8px;
    overflow: hidden;
}

.card__image {
    width: 100%;
    height: 200px;
    object-fit: cover;
}

.card__content {
    padding: 1.5rem;
}
Modificadores
.card--featured {
    border: 2px solid gold;
}

.card--horizontal {
    flex-direction: row;
}

.card__button--primary {
    background: #2D5BFF;
    color: white;
}

.card__button--disabled {
    opacity: 0.5;
    cursor: not-allowed;
}

🎭 Metodología OOCSS

Object-Oriented CSS - Estilos como objetos reutilizables

OOCSS trata los estilos como objetos reutilizables, inspirándose en la programación orientada a objetos. Su filosofía: separar responsabilidades para maximizar la reutilización.

1. Separar Estructura y Skin

Las clases estructurales (.box, .media) no definen colores ni fuentes. Los estilos visuales van en clases separadas (.theme-dark)

2. Evitar Dependencia Contextual

Los estilos deben funcionar en cualquier lugar del DOM. Evitar reglas como .sidebar .btn

🔧 OOCSS en la Práctica

❌ Sin OOCSS
.error-button {
    display: inline-block;
    padding: 10px 15px;
    border-radius: 4px;
    background: red;
    color: white;
}

.success-button {
    display: inline-block;
    padding: 10px 15px;
    border-radius: 4px;
    background: green;
    color: white;
}
✅ Con OOCSS
/* Estructura */
.button {
    display: inline-block;
    padding: 10px 15px;
    border-radius: 4px;
}

/* Skins */
.skin-error {
    background: red;
    color: white;
}

.skin-success {
    background: green;
    color: white;
}

HTML: <button class="button skin-error">Error</button>

📐 Metodología SMACSS

Scalable and Modular Architecture for CSS

SMACSS no impone una convención de nombres, sino que propone una arquitectura basada en categorías funcionales que permite modularizar el CSS y mantener una estructura clara.

Base

Estilos globales para elementos HTML: h1, a, button

Layout

Distribución de zonas principales: header, main, sidebar, footer

Module

Componentes visuales reutilizables: .card, .nav

🏷️ Categorías y Prefijos SMACSS

🏠 Layout (l-)

Estructura principal de la página

l-header l-sidebar l-grid

📦 Module (m-)

Componentes independientes

m-card m-modal m-carousel

🔄 State (is-, has-)

Estados dinámicos controlados por JS

is-active is-hidden has-error

🎨 Theme (theme-)

Variaciones visuales globales

theme-dark theme-corporate

📁 Estructura de Archivos SMACSS

📂 styles/
  📂 base/
    📄 reset.css
    📄 typography.css
  📂 layout/
    📄 grid.css
    📄 header.css
  📂 modules/
    📄 card.css
    📄 navigation.css
  📂 states/
    📄 states.css
  📂 themes/
    📄 theme-default.css

💡 Clave de SMACSS

Cada nuevo estilo debe encajar en una categoría específica. Si no sabes dónde va, probablemente necesitas repensar su propósito.

🔗 Integración con JavaScript

Las clases de estado (is-active, is-expanded) son perfectas para ser controladas desde JavaScript.

⚖️ Comparación de Metodologías

BEM

Fortaleza: Convención de nombres clara

Ideal para: Equipos grandes, alta predictibilidad

Ejemplo:
.card__button--primary

OOCSS

Fortaleza: Máxima reutilización

Ideal para: Patrones visuales repetitivos

Ejemplo:
.button .skin-primary .rounded

SMACSS

Fortaleza: Organización funcional

Ideal para: Apps con muchos estados

Ejemplo:
.m-card.is-active

🔀 En la práctica: Muchos equipos usan enfoques híbridos combinando nombres BEM + categorías SMACSS + separación OOCSS
