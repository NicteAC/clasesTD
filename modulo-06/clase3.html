¿Qué es Form Binding?

Binding es la conexión automática entre los datos del componente y los campos del formulario. En Vue usamos v-model para la conexión bidireccional.

data()
modelo
⇄
v-model
puente
⇄
input
vista

v-model es azúcar sintáctica para:
:value="dato" + @input="dato = $event.target.value"

Modificadores clave

ModificadorEfecto
.lazySincroniza en change, no en input
.numberConvierte el valor a Number
.trimElimina espacios al inicio y fin

v-model equivale a esto

<!-- Lo que escribís -->
<input v-model="nombre" />

<!-- Lo que Vue hace internamente -->
<input
  :value="nombre"
  @input="nombre = $event.target.value"
/>

<!-- Con modificadores -->
<input v-model.trim="nombre" />
<input v-model.number="edad" type="number" />
<input v-model.lazy="busqueda" />

// Verificar tipos en la consola:
// Sin .number → typeof edad === 'string'
// Con .number → typeof edad === 'number'

v-model en Todos los Tipos de Campo

Input / Textarea → string

<input v-model="nombre" />
<textarea v-model="descripcion"></textarea>

Checkbox booleano → boolean

<input type="checkbox" v-model="aceptaTerminos" />
// true si marcado, false si no

Checkbox múltiple → array

<input type="checkbox"
       v-model="intereses"
       value="tecnologia" />
<input type="checkbox"
       v-model="intereses"
       value="deportes" />
// intereses = ['tecnologia', 'deportes']

Radio → valor único

<input type="radio"
       v-model="envio"
       value="estandar" />
<input type="radio"
       v-model="envio"
       value="express" />
// envio = 'estandar' o 'express'

Select simple → valor único

<select v-model="pais">
  <option value="cl">Chile</option>
  <option value="ar">Argentina</option>
</select>

Select múltiple → array

<select v-model="seleccionados" multiple>
  <option v-for="op in opciones"
          :key="op" :value="op">
    {{ op }}
  </option>
</select>

Validaciones — Tres Momentos Clave

1

Computed — validación derivada en tiempo real

Computed properties que devuelven true/false. Se recalculan automáticamente cuando el dato cambia. Usá para saber si el form es válido antes del submit.

2

@blur — validar al salir del campo

El evento blur se dispara cuando el input pierde el foco. Ideal para mostrar el error solo después de que el usuario terminó de escribir — no en cada tecla.

3

@submit — validación completa al enviar

Llaman a un método que valida todos los campos y solo procesa si todo es válido. Acumulan errores en un objeto errores con propiedades por campo.

Patrón de validación con objeto de errores

data() {
  return {
    form: { nombre: '', email: '' },
    errores: { nombre: '', email: '' }
  }
},
methods: {
  validarNombre() {
    this.errores.nombre =
      !this.form.nombre.trim()
        ? 'El nombre es requerido'
        : ''
  },
  validarEmail() {
    const ok = /^[^\s@]+@[^\s@]+\.[^\s@]+$/
      .test(this.form.email)
    this.errores.email = ok ? '' : 'Email inválido'
  }
}

Template con mensajes de error

<div>
  <input
    v-model.trim="form.nombre"
    @blur="validarNombre"
    :class="{ 'error-input': errores.nombre }"
  />
  <span
    v-if="errores.nombre"
    style="color:red;font-size:.85rem"
  >
    {{ errores.nombre }}
  </span>
</div>

<!-- botón deshabilitado si hay errores -->
<button
  :disabled="!formularioValido"
>Enviar</button>

// computed:
formularioValido() {
  return !this.errores.nombre
    && !this.errores.email
    && this.form.nombre
    && this.form.email
}

  passwordValido() {

Caso práctico: Configurador de Producto

Los formularios con múltiples opciones conectadas a una propiedad computed permiten calcular valores derivados en tiempo real — como el precio total de un configurador.

data() {
  return {
    config: {
      modelo: 'basico',
      ram: 8,
      extras: []
    },
    precios: {
      modelos: { basico:800, avanzado:1200, premium:1800 },
      ram: { 8:0, 16:100, 32:250 },
      extras: {
        'GPU dedicada': 300,
        'Pantalla táctil': 200
      }
    }
  }
},
computed: {
  precioTotal() {
    let total = this.precios.modelos[this.config.modelo]
    total += this.precios.ram[this.config.ram]
    this.config.extras.forEach(e => {
      total += this.precios.extras[e]
    })
    return total
  }
}

template del configurador

<!-- Radio para modelo -->
<div v-for="(precio, mod) in precios.modelos"
     :key="mod">
  <input type="radio"
         v-model="config.modelo"
         :value="mod" />
  <label>{{ mod }} (+${{ precio }})</label>
</div>

<!-- Select para RAM -->
<select v-model.number="config.ram">
  <option :value="8">8 GB</option>
  <option :value="16">16 GB (+$100)</option>
  <option :value="32">32 GB (+$250)</option>
</select>

<!-- Checkboxes para extras -->
<div v-for="(precio, extra) in precios.extras"
     :key="extra">
  <input type="checkbox"
         v-model="config.extras"
         :value="extra" />
  <label>{{ extra }} (+${{ precio }})</label>
</div>

<!-- Total reactivo -->
<h2>Total: ${{ precioTotal }}</h2>

Antes del break — un tip

❌ No hacer

<!-- v-model directo sobre prop -->
<input
  v-model="$store.state.nombre"
/>
<!-- Vue 2: muta el store directamente
     Vue 3: causa warning -->

✅ Hacer

<!-- computed con getter/setter -->
nombre: {
  get() {
    return this.$store.state.nombre
  },
  set(val) {
    this.$store.commit('SET_NOMBRE', val)
  }
}

Para conectar v-model con Vuex: usá computed con getter y setter. El getter lee del store, el setter hace el commit.

Formulario Multipaso

Un formulario multipaso divide los campos en grupos lógicos mostrados con v-if según el paso actual. Mejora la UX al no abrumar al usuario con todos los campos a la vez.

Estado del wizard

data() {
  return {
    pasoActual: 1,
    totalPasos: 4,
    encuesta: { /* todos los campos */ }
  }
}

Navegación

<button
  v-if="pasoActual > 1"
  @click="pasoActual--"
>← Anterior</button>

<button
  v-if="pasoActual < totalPasos"
  @click="siguientePaso"
  :disabled="!pasoValido"
>Siguiente →</button>

<button
  v-if="pasoActual === totalPasos"
  @click="enviar"
>Enviar ✓</button>

estructura de pasos con v-if

<!-- Barra de progreso -->
<div class="progress">
  Paso {{ pasoActual }} de {{ totalPasos }}
  <div :style="{ width: (pasoActual/totalPasos*100)+'%' }"></div>
</div>

<!-- Paso 1: Datos personales -->
<div v-if="pasoActual === 1">
  <input v-model.trim="encuesta.nombre" />
  <input v-model="encuesta.email" />
  <input v-model.number="encuesta.edad" />
</div>

<!-- Paso 2: Intereses -->
<div v-if="pasoActual === 2">
  <div v-for="i in opciones" :key="i">
    <input type="checkbox"
           v-model="encuesta.intereses"
           :value="i" />
    <label>{{ i }}</label>
  </div>
</div>

<!-- Paso 3: Valoración con slider -->
<div v-if="pasoActual === 3">
  <input type="range"
         v-model.number="encuesta.satisfaccion"
         min="1" max="5" />
  <span>{{ encuesta.satisfaccion }}/5</span>
</div>

<!-- Paso 4: Resumen -->
<div v-if="pasoActual === 4">
  <pre>{{ encuesta }}</pre>
</div>

validación por paso + reset

computed: {
  pasoValido() {
    switch (this.pasoActual) {
      case 1:
        return this.encuesta.nombre.trim() !== ''
          && /^[^\s@]+@[^\s@]+\.[^\s@]+$/
            .test(this.encuesta.email)
          && this.encuesta.edad > 0
      case 2:
        return this.encuesta.intereses.length > 0
      default: return true
    }
  }
},
methods: {
  siguientePaso() {
    if (this.pasoValido) this.pasoActual++
  },
  enviar() {
    console.log('Encuesta:', this.encuesta)
    // Reset completo
    this.pasoActual = 1
    Object.assign(this.encuesta, {
      nombre: '', email: '',
      intereses: [], satisfaccion: 3
    })
  }
}

Arrays Dinámicos en Formularios

Cuando un formulario necesita un número variable de ítems — como líneas de un pedido o ítems de una factura — usamos un array en data() con v-for para renderizar y push/splice para agregar/eliminar.

data() {
  return {
    pedido: {
      cliente: '',
      items: [
        { producto: '', cantidad: 1, precio: 0 }
      ]
    }
  }
},
computed: {
  total() {
    return this.pedido.items
      .reduce((sum, item) => {
        return sum + (item.cantidad * item.precio)
      }, 0)
  }
},
methods: {
  agregarItem() {
    this.pedido.items.push({
      producto: '', cantidad: 1, precio: 0
    })
  },
  eliminarItem(idx) {
    this.pedido.items.splice(idx, 1)
    if (this.pedido.items.length === 0) {
      this.agregarItem()
    }
  }
}

template de la lista dinámica

<input v-model.trim="pedido.cliente"
       placeholder="Cliente" />

<div
  v-for="(item, i) in pedido.items"
  :key="i"
  style="display:flex;gap:.5rem;margin:.4rem 0"
>
  <input
    v-model.trim="item.producto"
    placeholder="Producto"
    style="flex:2"
  />
  <input
    v-model.number="item.cantidad"
    type="number" min="1"
    style="flex:1"
  />
  <input
    v-model.number="item.precio"
    type="number" min="0"
    style="flex:1"
  />
  <button @click="eliminarItem(i)">🗑️</button>
</div>

<button @click="agregarItem">+ Agregar ítem</button>

<h3>Total: ${{ total.toFixed(2) }}</h3>

Componente Personalizado con v-model

Para usar v-model en un componente hijo, necesitan implementar el contrato que Vue espera: recibir modelValue como prop y emitir update:modelValue.

Esto permite que el padre escriba:
<CampoTexto v-model="nombre" />
y Vue lo traduzca a:
<CampoTexto :modelValue="nombre" @update:modelValue="nombre = $event" />

Padre — uso limpio

<CampoTexto
  v-model="contacto.nombre"
  label="Nombre"
  :required="true"
/>
<CampoTexto
  v-model="contacto.email"
  label="Email"
  tipo="email"
/>

CampoTexto.vue — hijo

<template>
  <div class="campo">
    <label>{{ label }}</label>

    <input
      v-if="tipo !== 'textarea'"
      :value="modelValue"
      @input="$emit('update:modelValue',
              $event.target.value)"
      :type="tipo"
      :required="required"
    />

    <textarea
      v-else
      :value="modelValue"
      @input="$emit('update:modelValue',
              $event.target.value)"
    ></textarea>

    <span v-if="error" class="error">
      {{ error }}
    </span>
  </div>
</template>

<script>
export default {
  props: {
    modelValue: String,
    label: String,
    tipo: { type: String, default: 'text' },
    required: Boolean,
    error: String
  },
  emits: ['update:modelValue']
}
</script>

computed: {
  total() {
    return this.pedido.items
      .reduce((sum, item) => {
        return sum + (item.cantidad * item.precio)
      }, 0)
  },
  pedidoValido() {
    if (!this.pedido.cliente.trim()) return false
    return this.pedido.items.every(item =>
      item.producto.trim() !== ''
      && item.precio > 0
      && item.cantidad > 0
    )
  }
},
methods: {

    if (this.pedidoValido) {
      alert(`Pedido de $${this.total.toFixed(2)} enviado`)
      // reset
      this.pedido.items = [{
        producto:'', cantidad:1, precio:0
      }]
    }
  }
}

  total() {
    return this.pedido.items
      .reduce((s, i) => s + (i.cantidad * i.precio), 0)
  },
  pedidoValido() {
    return this.pedido.cliente.trim() !== ''
      && this.pedido.items.every(i =>
        i.producto.trim() && i.precio > 0
      )
  }
},
methods: {
  agregarItem() {
    this.pedido.items.push({
      producto:'', cantidad:1, precio:0
    })
  },
  eliminarItem(idx) {
    if (this.pedido.items.length > 1)
      this.pedido.items.splice(idx, 1)
  },
  confirmar() {
    alert(`Pedido de ${this.pedido.cliente}: $${this.total.toFixed(2)}`)
    this.pedido.items = [{ producto:'', cantidad:1, precio:0 }]
  }
}

Buenas Prácticas en Formularios Vue

🏗️ Estructura de datos clara

  • Un objeto por formulario con todas sus propiedades
  • Valores iniciales para todos los campos
  • Objeto errores paralelo con mismas keys

✅ Validación progresiva

  • Computed para estado global del form
  • @blur para validar al salir del campo
  • Validación completa solo al enviar

🔒 Seguridad

  • Nunca confíes solo en validación del cliente
  • Sanitizar datos antes de enviar a la API
  • Tokens CSRF en formularios que modifican datos

⚡ Rendimiento

  • Usar .lazy para campos que no necesitan update por tecla
  • Debounce para búsquedas en tiempo real
  • v-if para secciones que no siempre son necesarias

♻️ Componentes reutilizables

  • Un CampoTexto.vue genérico para todos los inputs
  • Pasá label, tipo, error, required como props
  • Implementá el contrato modelValue / update:modelValue

💡 Para forms complejos, considerá Vuelidate o VeeValidate — librerías de validación dedicadas para Vue.
